## Fixture and provenance

The five files are from the NIST MBE PMI Validation and Conformance Testing Project's
public STEP archive: the ZIP at `https://www.nist.gov/document/nist-pmi-step-files`,
downloaded and unpacked in a fresh throwaway directory (untrusted-data rule), then vendored
into `crates/fieldsmith-verify/tests/fixtures/` unchanged. Each header says it itself, e.g.
`FILE_DESCRIPTION(('CTC-01 geometry only from the NIST MBE PMI Validation and Conformance
Testing Project'),...)`, file dates 2015; the files are US government work (public domain).
Suffixes `_rd`/`_rc` are the archive's own derivative naming. Coverage shapes: CTC-01/02
are a machined-plate family with holes and conic fillets; CTC-03 is a thin-shelled cup;
CTC-04 carries a torus; CTC-05 is the conversion-based (inch) counterpart of CTC-02's
family.

## The unit-context finding (a GOAL criterion amended)

GOAL's draft criterion said units come from the file's `SI_UNIT`. CTC-05 disproves it: its
single `GLOBAL_UNIT_ASSIGNED_CONTEXT((#6596,#6599,#6600))` — the only unit context in the
file, and the one every geometry representation references — declares `INCH` (a
`CONVERSION_BASED_UNIT` with factor `LENGTH_MEASURE_WITH_UNIT(2.54E1, mm)`). The six
`SI_UNIT(.MILLI.,.METRE.)` entities in the file are not the file's unit: they are only the
factor bases inside those conversion entities. Raw coordinates are inch-scale (−10.375 in),
and ×25.4 maps them onto CTC-02's millimetre geometry — both files model the same part
family. The reader resolves the file's unit from its unit context (its `units_of` takes the
first length unit in the context), reports `INCH`, and applies the 25.4 mm scale; GOAL line
C3 is amended to say the file's unit context in the M10 commit.

## The tessellation defect finds (all fixed in-tree, tests carry them)

- **Flux hole double-count**: faces carrying internal voids paid the void area twice in the
  signed-volume sum (~6 % over on CTC-01); the per-face integrals now follow the trimmed
  region.
- **`flip_tris` → `orient_solid`**: per-face winding flips were replaced by a propagation
  across shared edges with a global side decided from the flux sum (the flux stays None on
  B-spline faces and winding is then propagated only).
- **CTC-01's authoring slop**: its edge-precision floor is ~0.003 mm, which caps usable
  chords independently of the derived default (named in the ladder below).
- **Master-sampling T-vertices**: where two faces share a conic edge, the shared edge's
  samples come from one master polyline, otherwise one face's quarter-arc endpoint meets
  the other's full-circle spacing and the weld misses (inherent where 4 ∤ N).
- **Half-cone seam window (this milestone's last find)**: a cone's (u,v) seam sat inside the
  half-cone sampling window, and the closure fix silently picked hoist or pull by roundoff;
  the decision is now made by the bulk span rule — pull when the bulk span does not
  shrink by hoisting (ties break to pull). Variant tests: reverting the closure keeps
  CTC-02 at 75 open edges and CTC-05 at 19; keeping it gives 0/0 and moves CTC-01's mesh
  purely by a one-sample seam realignment (same vertex set, 5/5 runs byte-stable).

## STEP budget row (provisional → measured)

GOAL's table says "parse + tessellate a ≤ 50 MB file | ≤ 30 s (provisional)". Measured on a
synthetic 49.9 MB file (9 120 separate 10-mm-cube `MANIFOLD_SOLID_BREP`s, 54 720 planar
faces, generated by a throwaway script and read through the same `tessellate`): parse
1 987 ms + tessellate 324 ms = 2.3 s — 13× under the budget with only plane geometry. The
budget holds at the size ceiling, but the honest reading is: the number is parse-dominated
and B-spline-saturated files (dense NURBS surfaces) tessellate slower per face than this
probe; CTC-05's 126 k triangles over 45 340 faces (6 ms + 157 ms) is the real-file anchor.
The budget row stays at ≤ 30 s with this measurement named.

## Limits

- CTC-05's divergence being negative is expected where no flux potential exists (the
  B-spline faces) — the mesh's own signed volume is reported, and PrusaSlicer's independent
  volume lands on the same magnitude; no analytic reference binds on that file.
- Cone coverage > 1 (CTC-03 up to 2.0253, CTC-05 face 82 at 1.5405) is a metric artifact on
  thin-shelled/sheet faces: the parameter-space area double-counts where the trimmed region
  folds back; the min-coverage column still reports the honest lower edge (0.9795/0.9936).
- Assemblies (`NEXT_ASSEMBLY_USAGE_OCCURRENCE`) are refused by name: placements are not
  applied by the tessellator; a multi-part assembly with transforms is a named failure, not
  a silently misplaced import.
- The voxel `volume` estimate is a tool bound, not a proof: on CTC-01
  (`fieldsmith volume`, grid 5 mm) it reads 14 604 709 ± 2 034 mm³ while the B-rep flux
  reference is 14 643 208 mm³ — a 0.26 % systematic offset outside that narrow half-width
  (the bound under-covers deterministic grid error on a curved boundary); the 1 % criterion
  above is carried by the flux-vs-divergence leg, not by this estimate.
- Reference-task deviations, named (see the run section below): the fill legs run at 1:10
  scale — document transforms carry translate+rotate only, a STEP `--units` override
  cannot shrink mm-baked coordinates, and full-size cell-6 gyroid needs ≈31 M voxel
  cells — via a ×0.1-scaled STL re-import of the part's own solid export (same faces,
  regions, load and material, named in the report). The static leg is a wiring leg, not
  a stress-accuracy rung: 400 N on an ≈18 kg part reads 0.01 MPa against PETG's ≈
  55 MPa yield.
- Graded fill on a *mesh-leaf* document has no export route to `manifold = yes` at
  prescribed skin (the uniform path welds sheet/wall tangencies; the adaptive path
  opens seams across the trilinear body's offset creases — A/B isolation and the
  bounding skin=0 `manifold = yes` run in the report section). No earlier run had taken
  a mesh-leaf graded fill to the slicer; v0.1's slicer-manifold evidence was all on
  analytic (expr) bodies.

## Reference task run on a foreign fixture (CTC-01, CLI, recorded 2026-10-12)

not author; provenance above), numbers as printed by the CLI. All wall times are from
this workstation; the full-size modal rung (eigen 148.5 s) and the 1:10 solid solve
(56.6 s) overlapped, so those two carry cross-contention; the rest ran alone.

**Import (step 2)** — `fieldsmith import nist_ctc_01_asme1_rd.stp --units mm --up z`:

across the PL-crease bands of a mesh-leaf body offset — is named as the pipeline's
next defect item, surfaced by this run because no earlier run took a mesh-leaf graded
fill to the slicer.
