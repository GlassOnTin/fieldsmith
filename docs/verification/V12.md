## Fixture and provenance

`multiple_cylinders.3mf`, 1981 bytes, from the 3MF Consortium's public samples
(repository `github.com/3MFConsortium/3mf-samples`, path `examples/core/multiple_cylinders.3mf`,
© 2018 3MF Consortium, BSD-2-Clause). It is vendored as
`crates/fieldsmith-verify/tests/fixtures/multiple_cylinders.3mf` with the licence note; the
download itself went into an empty scratch directory. The file holds one mesh object
(`Cylinder`, 88 triangles) with a `basematerials` group on the object, instanced six times
by `<build>` items carrying transforms (translation, a 90° rotation about z, and a mirror
among the six; the mirror's winding reversal is covered by a reader test). Nothing in the
fixture or its import was authored here.

The reader path: sizes and CRC come from the central directory, so the sample's data
descriptors (local headers leave sizes 0) inflate cleanly — a foreign-writer pattern the
previous local-header-only zip reader refused. Item transforms bake into the imported
vertices with the model unit applied to the translation but not to the linear part; the
negative-determinant item reverses triangle winding to preserve volume sign. One leaf per
build item; the id chooser appends 1, 2, 3… for repeated names. Import does not adopt the
file's material ids as fieldsmith labels (another tool's ids are not fieldsmith materials);
leaves arrive unlabelled and inherit the document material.

## The import and reader legs (in CI)

`crates/fieldsmith-verify/tests/v12_multivolume.rs` (4 tests) runs the vendored fixture
through the real import chain, composes the six leaves with a labelled box, checks the
validate warning, resolves a patch region (`Cylinder1.p1`) and a face region (`plate.py`)
onto the analysis surface disjointly, and exports per volume: mesh volume within 1 % of the
field reference per volume, read-back gives 7 objects with the material labels (petg ×6,
abs). `fieldsmith-mesh/tests/readers.rs` (25 tests) covers the acceptance and rejection
surface: build-item expansion with winding, unit-scaled translations, duplicate object id,
unknown item `objectid`, item without `objectid`, component containers, malformed transforms
(wrong count, non-number), unclosed `<build>`.

## The headless compose, solve, and re-export (recorded 2026-10-09, CLI run)

The composed document (six imported leaves plus):

```
box plate size=(80, 42, 4) at=(31, 9.89, 10) round=0.5
material abs on plate

region hold = Cylinder1.p1
region press = plate.py
support fixed hold fixed=xyz
load press press force=(0, 0, -900) case="Press"
```

— a slab 80 × 42 × 4 mm passing through all six cylinders (the sample's spacing is 21 mm
columns, 20.7964 mm rows), labelled `abs` against the document's `petg`.

- `check`: `7 shapes, 2 regions, 1 supports, 1 loads, material petg`, then `ok` and the
  mixed-material warning quoted in the table above.
- `solve`: the warning prints before the run; the solve is single-material petg:
  42 804 elements (P2), 200 643 DOF, element size 2.43 mm; mesh 66 ms, solve 2339 ms,
  30 iterations, min dihedral 10.2°; Press: peak von Mises 102.50 MPa (element centroids;
  nodal 137.98), max deflection 1.9726 mm.
- `export --3mf`: the per-volume path meshes each add-node alone at h = 0.25 mm and labels
  node material else document material. Per-volume field references: each cylinder
  6192.3 ± 8.0 mm³, the plate 13411.2 ± 2.5 mm³; the report's union line measures the whole
  body 44 969.7 ± 58.6 mm³ with the mesh at 44 970.3 (Δ +0.001 %), and
  6 × 6198.18 + 13378.29 − 44 970.3 = 5 597 mm³ is the six cylinder∩plate overlaps the
  union collapses. Package XML: 7 objects named after the nodes, 1 `basematerials` with 2
  bases; pindex assignment follows the labels.
- PrusaSlicer 2.9.6 `--info`: 7 volumes, all `manifold = yes`; volumes as in the table.
  `--info` reports each object in local coordinates, so names and materials were confirmed
  from the package XML above (the CLI shows neither).

## A second foreign file (robustness, not the case's fixture)

The Consortium's `cube_gears.3mf` (263 230 bytes, 17 objects named `gear 1`…`gear 17`
except the file's seventh object, `cube 7`; 25 692 triangles total) imports to 17 leaves
(`gear_1`…`gear_6`, `cube_7`, `gear_8`…`gear_17`; spaces sanitize to underscores, no dedupe
needed). Seven of the seventeen foreign meshes carry genuinely open tessellations (12–72 open edges per leaf; the
open-edge sets differ between same-triangle-count objects, so they are properties of the
file's own meshes, not of the import); `check` names each leaf's count. A 17-leaf document
exceeds the 8-leaf preview budget: `check` reports it as an error (exit 1) — correct,
such a document is not previewable in WebGL2 — while `solve` and `export` do not gate on
`validate()`, so headless use is unaffected.

## Limits

- The browser Make-lens export (wasm `threeMfBytes`) still writes one union object with the
  document material; the per-volume path is CLI-only today.
- `material abs on <node>` labels are document-level; they travel to the slicer and drive
  the validate warning. The solve stays single-material (the plate above was solved as petg).
- Item transforms are baked into vertices; the document node keeps its default transform.
- The 8-leaf preview budget comes from WebGL2's 16-sampler fragment guarantee (two
  sampler3D per leaf), reasoned, not measured on a GPU.
- zip64 archives are refused by name; component containers are refused by name. Neither is
  a tessellation of a foreign file here — both are named refusals.
